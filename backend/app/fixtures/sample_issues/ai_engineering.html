AI Engineering Digest (sample issue)

1. Choosing an embedding size

The Gemini embeddings guide says the models output 3072-dimensional vectors by default and accept an output dimensionality setting for smaller vectors, recommending 768, 1536 or 3072. Smaller vectors from gemini-embedding-001 need to be normalised by the caller. Embeddings guide

2. Getting JSON you can trust from a model

The Gemini API can be asked for structured output: you supply a JSON schema and the response is constrained to it. The guide still recommends validating the result in your own code before using it. Structured output

3. Vector search lands in the database you already use

Another week, another database adding vectors: Firestore's guide shows how to store embeddings next to the rest of a document and query the nearest neighbours, so small apps may not need a separate vector store. Firestore vector search

4. Retrieval-augmented generation, in plain words

Google Cloud's explainer describes retrieval-augmented generation as fetching relevant documents first and giving them to the model with the question, so answers can be grounded in those sources instead of only in what the model memorised. What is RAG?

5. Reader question

A reader asked why we keep repeating "evaluate before you ship". Short answer from the editors: write a small set of test questions with expected answers before changing prompts, so you can tell whether a change helped. No link this week; we will cover eval tooling in a later issue.
